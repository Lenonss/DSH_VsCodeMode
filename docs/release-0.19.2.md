# dsh-vscode-mode 0.19.2

发布日期：2026-10-23

## 资源管理器缺失目录自愈

历史展开记录可能保留已被外部删除或改名的子目录。树上已没有对应行，用户无法手动折叠，而恢复展开与跟随刷新会反复请求该目录，导致「目录不存在」红条常驻。

- 无可用缓存的子目录返回「目录不存在」时，自动移除对应展开记录，通过现有 300ms 防抖持久化；兼容 host 已附带路径的文案。
- 根目录缺失仍展示错误，不静默隐藏；权限不足、不是目录及其他读取错误仍保留，子目录错误附带相对路径。
- 不修改请求 token，保留 finally 的加载态清理，避免永久「加载中」。目录重建后不自动展开，仍可手动展开。
- 有旧条目缓存时保留原有降级行为。本次不修改 host RPC，也不自动清理工作区历史临时目录。

## 验证与边界

新增 8 个组件回归用例，覆盖恢复与持久化、10 秒跟随刷新、根目录错误、非缺失错误、加载态清理、重建后手动展开及缓存降级；针对性测试 5 个文件共 57/57 通过。

发布前执行类型检查、完整 JavaScript 发布测试套件及 Host / Client 构建；最终结果以发布记录和 CI 为准，不将构建通过等同于真实 GUI 验收。

本次真实 GUI 冒烟尚未完成，用户已明确接受该发布缺口。发布不自动安装、修改 profile 或重启当前 DSH 实例。安装更新后请强制刷新页面；若同时升级旧版 Host 功能，请按对应历史版本说明重启 DSH。

## 已知行为与回退

外部更新期间若子目录暂时消失且无缓存，会被折叠一次；恢复后手动展开即可。失效展开记录被移除后，回退旧版本不会恢复该展开状态，但不影响磁盘文件。必要时可重新安装 0.19.1；不覆盖已发布版本或重打 tag。
