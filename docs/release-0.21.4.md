# v0.21.4：明确任务受理与诚实草稿降级

作者：ddj，2026-10-29。

## 变更

- 新增可选详细发送结果，区分 accepted、rejected、unavailable、unknown、submitted 与 cancelled；旧 sendTask / apiSessionPrompt 仍返回 boolean。兼容字段保留历史返回语义，legacy true 可能只代表调用过提交，不等于明确受理；同一次调用不会为了获取详细结果再发送一次。
- SVN 深度分析只有 accepted 才启动原方案轮询。unknown、submitted、cancelled 不另填草稿、不跨通道重试、不启动等待，提示用户检查目标会话，避免不明结果触发重复任务。
- 明确拒绝、发送前不可用或创建目标失败时，只向实际当前会话插入手动草稿，按当前目标重建提示词并显示“已填入当前草稿，请手动发送”；不自动 submit，不伪称后台任务已运行。
- 旧注入对象缺详细 API 时，明确提示本次未自动发送，不调用旧 boolean 接口尝试，也不另填草稿。发送后收尾异常保守归为不明或取消，不能误导为安全重发。
- 保留目标会话的单次 retain/release 与单通道发送。legacy composer 既有整篇 setDraft 政策未修复，本版不宣称解决旧草稿覆盖行为。

## 验证与已知边界

已完成针对性隔离回归：底层 Session Controller ownership 与详细结果 37 项通过（48 项按名称过滤），真实 SVN caller 16 项通过。覆盖真实详细门面到真实 caller 的拒绝/抛错联接、取消时序、历史 boolean、收尾异常与真实草稿插入；mock 与合成树不代表全部现场行为。

真实 GUI 验收使用当前 Web 开发 link 客户端 rev458288ddb012：专用隔离 SVN 工作副本中，公开按钮仅点击一次，出现 accepted 专属通知，唯一正确目标收到 prompt 并开始 agent 执行。此证据证明真实发送受理链，不证明分析完成。

完整 SVN status/diff、分析方案生成、svn_plan_submit 投递及面板结束等待因沙箱准备 `SetNamedSecurityInfoW failed (Win32 5)` 未完成；未批准目标待审批命令、改 ACL 或重发任务。用户明确接受本批发送链验收继续发布，此接受不自动延伸到后续版本。真实异常分支、legacy、全部切会话/卸载竞态未逐项现场验证。

完整 JS 发布套件按本版发布门禁执行，结果以对应 CI / 发布验收记录为准，不用定向测试数字代替完整套件。未进行 Unity 全量验证。

当前实例曾构建刷新开发 link 客户端；Host 未重启，不能称 Host 整体升级，也不能称已安装 npm 0.21.4。公开发布与当前实例部署分别核验，发布不自动安装、刷新或重启。

## 升级

待 npm 精确版本或 GitHub Release 资产可查询后，按 README 三选一安装示例选择实际目标 profile。升级操作由用户自行安排；若需要重新加载 Host，应由用户确认并执行，不由发布流程自动重启。保留原配置与隔离验收证据，不执行生成的 SVN 方案或真实提交。

本版无新增依赖、配置迁移或破坏性数据迁移。回退可选择原版本，但已发送任务不会因客户端降级而撤销，受理不明时请先检查目标会话，勿重复发送。
