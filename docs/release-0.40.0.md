# dsh-vscode-mode v0.40.0 — 测试验收模式（/test-check）

日期：2026-11-26　基线：与 0.39.0 相同（Web `@deepseek-ai/dsh@0.2.3-alpha.2` / 桌面 `0.2.2-rc.5`）
上一版：v0.39.0

## 背景

一次改动的验收结果散在三处：AI 说「都验过了」、人只记得点了哪几下、报告里没有可复现的证据。
`/test-check` 把这套流程落成**一项一条、每条带证据、人和 AI 看同一张单**：验收单存在项目里，
结果落盘成事件文件，收尾导出可交付的 HTML 快照。

## 形态

```
/test-check <任务>  ──▶ 验收单 .dsh/test-check/<id>/items.json
                          │  AI 每验一条：test_check_report（item/status/summary 必填）
                          ▼
                        events/*.json  ──▶ 底部 chip「验收 x/y」+ 验收单页签
                          │
                          ▼
       test_check_finish ──▶ docs/acceptance-<id>.html（单文件、无脚本、可进库）
```

- 独立模式：与 `/plan`、`/html-plan` 并列互斥，进入其一即收起其它模式的规则。
- 状态口径：`pass` 没有证据只算「无证据」、不计通过；被验文件改过自动变「需复验」。
- `<id>` 由任务文本派生，同一句话再进模式回到同一张单。

## 侧栏「测试验收」面板

| 区块 | 内容 |
| --- | --- |
| 使用说明 | 浮窗讲清命令、chip、工具参数与状态口径（Esc / 点遮罩关闭） |
| 专属技能 | 只读展示随包 `skills/dsh-vscodemode-test-check/SKILL.md` 全文，可复制 |
| 项目测试规范 | 等宽编辑框，保存后下一条消息生效；空内容＝删除文件回到默认；超 8 KB 提示会被截断 |
| 当前验收项 | 当前单的条目速览（状态点 + 标题 + 标签），点行打开验收单页签 |
| 全部验收单 | 项目内每张单一行，点行用系统程序打开快照；快照缺失的行标「快照缺失」并给移除入口 |

规则文件固定在 `<项目根>/.dsh/test-check/policy.md`，写盘路径不可注入；保存与重置会立刻清掉
mtime 缓存，同一条消息里就能读到新规则。默认规则是 8 条通用条款（跑什么测试、证据写什么、
真机行为怎么算），不含本仓库私有路径。

## 同时修正

- 附件落盘逻辑从 `/html-plan` 命令里抽成 `src/attachmentBytes.ts`，两个模式共用一套读取、回滚与字节归一。
- 侧栏面板取数拆成 `usePolicyDraft` / `useSheetSnapshot` / `useSheetActions` 三个 hook，面板只负责渲染。
- 全部单列表加 30 秒缓存（写盘、建单、导出、删除会主动失效），刷新按钮强制重扫。
- 移除按钮在有快照的行上收进悬停/聚焦态，避免误删；列表行支持键盘 Enter/Space。

## 新增 RPC

`edrv.testCheck.*`：`get` / `report` / `snapshot`（模式本体）、`policy.get` / `policy.save` /
`policy.reset` / `skill` / `sheets` / `remove`（面板）。

## 验收

1. `/test-check 验收这次改动` → 底部出现 chip，验收单页签给出建单引导。
2. 侧栏出现「测试验收」页签；说明与技能两个浮窗 Esc、点遮罩都能关。
3. 改规范保存 → `.dsh/test-check/policy.md` 出现，规则段末尾就是新内容；清空保存或点重置 → 回到默认。
4. 全部单列表点行用系统程序打开快照；手工删掉快照后刷新，该行标「快照缺失」，移除会同时删单目录与快照。
5. `/plan`、`/html-plan` 与验收单页签行为不变。
