# v0.21.3 — MCP 初始化失败结果与安全收尾解耦

## 变更

- MCP 初始化将调用者结果与资源收尾分开管理：已进入 startup 的调用者在初始化失败、取消或启动截止时间到达时及时收到拒绝，不再等待旧 work/close 完成才获知失败。
- 收尾责任不随调用者失败丢失。旧 work 或 close 尚未确认完成时，连接仍处于 stopping、占用冷启动名额并阻止同 key 重建；迟到的初始化结果不会发布工具或复活连接。确认真实收尾后才开始原有 5000ms 冷却，两名额上限不变。
- 同步关闭抛错、异步关闭拒绝及迟到创建后的关闭失败均保留资源围栏，不把关闭失败当成已完成清理，也不开放重叠替代连接。
- 增加可控时钟与屏障回归，覆盖调用者及时拒绝、双名额仍被占用、晚到资源的关闭责任及自然收尾后的恢复；官方 HTTP 失败恢复测试等待自然收尾并核验零残留，再验证显式 refresh 恢复。

- 官方 bridge 隔离 fixture 迁移到当前公开 native 执行器及批调用契约，保留工具、资源、提示词与撤销隔离断言；这是测试契约兼容修正，不代表生产执行器故障修复。

## 验证与已知边界

- 本轮独立定向验收：类型检查通过；Pool 20/20、Runtime 精确 7/7、官方实装隔离 HTTP 失败恢复 1/1 通过。完整 JS 发布套件、构建与 CI 结果以实际验证和对应 Release 工作流为准，不预先宣称通过。
- 当前运行 Host/GUI **未加载本版、未部署、未验证**。用户仅对本批接受官方实装隔离模块与完整 JS 发布套件作为替代验收，此接受不延伸至后续批次，也不代表当前实例已升级。
- 首次连接曾约 60 秒后超时的根因仍未知；本版未完成修复后的真实 CodeGraph stdio 或当前 Host 调用验收，不宣称解决该现场首次超时。
- gamma 等冷启动队列、connect 前的 tail/barrier，以及 refresh/retire/dispose 仍可能等待不合作的底层任务；本版不承诺整体流程有界，不强行释放尚未确认安全的名额。官方 HTTP 自然收尾成功不证明所有不合作传输都能关闭，也不等于生产环境无泄漏。
- 保留历史版本的 XLSX、差异导航、缺失文件审查及会话 Controller 等既有能力与各自验收边界，不增加其本版已验证范围。

## 升级

公开发布完成后，可使用插件管理器或安装 `dsh-vscode-mode@0.21.3`；替换包后由用户重启目标 DSH Host 并强制刷新原页面。

本次发布不自动安装至任何 profile，不部署、不重启当前 DSH，不修改用户 MCP 配置。依赖、存储格式与历史数据迁移规则未改变。
