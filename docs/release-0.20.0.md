# v0.20.0 — 官方净差异持久化与审查入口整合

## 变更

- 官方 `workspace/changes` 的轮次摘要及差异块作为历史展示依据，保存到 DSH home 的工作区 SQLite，不从工具参数猜测官方净差异。
- 复用现有差异列表、角标、文件导航与对比入口，区分官方净差异和旧工具记录，不新增独立审查栏；同一文件的官方记录优先，旧记录保持兼容。
- pending 不因后续轮次、手动保存或无法定位而自动采纳/清理。可标记已审，也可打开当前文件编辑；保存不等于已审。
- 决策带事件身份、修订校验及操作去重。缺少可信历史全文和原始字节时禁用拒绝写回，避免从 patch 猜测恢复内容。
- 修正官方文件路径身份解析；启动补采读取原始事件列表并排除继承事件。已有持久化记录的身份修复独立于旧摘要读取，保留 ID、差异内容和审查状态。
- 官方差异操作条改用主题感知的灰色文字与边框，修正浅色背景上反向白字不可读的问题。

## 升级与边界

- 安装升级后请重启 DSH 加载 Host 采集回调，并刷新页面。公开发布不自动升级、部署或重启当前实例。
- SQLite 迁移保留既有数据；不要删库来触发补采。回退旧版前请备份 DSH home 的工作区数据库；旧版不会提供本版官方审查入口，不保证向旧版本数据库降级写入。
- 官方摘要及差异在上游内存中可能已失效。已经落盘的数据可重读；从未保存成功且上游已失效的旧轮次只记录采集缺口，不能恢复，也不会伪造历史。
- 本版不是完整 Undo 系统：官方仅有差异块时，原始历史只读。全文基线及逐块安全回滚留待独立任务。

## 验证与已知项

- 当前 GUI 已验证真实文件名、历史差异展开、重启后第 8 与第 13～15 轮数据读取，以及浅色主题操作栏配色。
- 隔离临时 SQLite + 真实 RPC handler 验证手动保存不改变 pending、标记已审同步列表与角标数据、关闭重开数据库后保留已审状态，且已审操作不写文件；未修改真实用户记录。
- 上述决策回归不是浏览器点击按钮的端到端测试；深色主题和其他平台的真实 GUI 本轮未现场验收，用户已明确接受这些发布缺口。
- 原先误开的 `[object Object]` 页签可能残留在用户已保存的界面状态中，可手动关闭；不自动删除页签或改动审查决定。
